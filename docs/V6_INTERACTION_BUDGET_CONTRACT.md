# V6 Interaction and Parameter Budget Contract

Status: BINDING RESEARCH CONTRACT

## Purpose
Prevent combinatorial parameter growth, duplicated filters and accidental overfitting as more Research Lab tools are added.

## Default order
1. test one family in isolation;
2. retain negative and neutral results;
3. only families with defensible isolated evidence may enter targeted interactions;
4. pairwise interactions precede higher-order combinations;
5. third-order combinations require an explicit written rationale and fresh validation plan.

## Parameter budget
A research hypothesis must declare its effective free-parameter count before evaluation.
- fixed/predeclared constants still count when multiple alternatives are tested;
- train-derived thresholds count by derivation rule, not by every realized WF value;
- diagnostic-derived threshold families are marked separately and require fresh evidence;
- equivalent or highly correlated conditions should be collapsed conceptually before grid expansion.

## Grid discipline
Large Cartesian products are forbidden by default.
Before adding a dimension, record:
- what distinct market mechanism it represents;
- why an existing feature does not already encode the same information;
- expected incremental evidence value;
- maximum combinations added;
- stop condition for non-improvement.

## Interaction budget
For a retained family:
- isolated test first;
- then a small predeclared pairwise set against the highest-value independent families;
- no exhaustive all-family cross product;
- interactions discovered from OOS diagnostics become new hypotheses, not immediate extensions of the same test.

## Redundancy rule
If two filters are materially measuring the same underlying state (for example volatility, range expansion or trend persistence), test their incremental contribution conditionally. A filter with negligible incremental information should be retained as a research note or rejected, not stacked merely because it is individually plausible.

## Stop rules
Stop expanding a branch when one or more apply:
- trade count falls below meaningful interpretation;
- PF/Return-R improves only in a narrow parameter edge;
- improvement disappears under cost stress;
- broad-era stability deteriorates materially;
- the new filter mostly duplicates an existing condition;
- complexity rises without clear incremental evidence;
- the hypothesis was generated by the same OOS data now being used to validate it.

## Complexity accounting
Every retained interaction report must state:
- number of component families;
- number of free/tested parameters;
- number of combinations evaluated;
- baseline trade count vs filtered trade count;
- incremental Return-R/PF;
- no-trade increase;
- whether the complexity increase is justified by stable evidence.

## Promotion
Complexity is a cost. A more complex candidate must outperform a simpler alternative not only in headline metrics but also in stability, explainability and reproducibility. No interaction auto-promotes into V11.2, Paper or Live.
